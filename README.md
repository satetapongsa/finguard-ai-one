# FinGuard AI – Regulatory Compliance Agent

ผู้ช่วยสำหรับทีม Compliance ของธนาคาร: ดึงประกาศของธนาคารแห่งประเทศไทย (ธปท.) จริงทุกเช้า
แยกเป็นภาระหน้าที่ทีละข้อ เทียบกับนโยบายของธนาคาร ว่าข้อไหน
**ครอบคลุมแล้ว / ครอบคลุมบางส่วน / ยังไม่มี / ขัดกับ policy** แล้วสร้างงานและแบ่งให้พนักงานในแต่ละฝ่าย

ใช้ AI จาก [Groq](https://console.groq.com) ถ้ายังไม่ได้ตั้ง API key หน้าวิเคราะห์จะใช้การวิเคราะห์แบบกฎแทน

## ฟีเจอร์

- **ล็อกอิน 2 บทบาท** – **หัวหน้า** อนุมัติ / ไม่อนุมัติงาน และกดรันงานประจำวันได้ · **พนักงาน** เห็นเฉพาะงานของตัวเองและปิดงานได้
  ทุกการเปลี่ยนแปลงเก็บประวัติว่าใครทำอะไรเมื่อไหร่ (audit trail)
- **เลือกธนาคาร** (มุมขวาบน) – Bank A (จำลอง) หรือธนาคารจริง 5 แห่ง: กสิกรไทย, ไทยพาณิชย์ (SCBX), กรุงไทย, กรุงเทพ, กรุงศรีอยุธยา
- **สรุปประจำวัน** (ธนาคารจริง) – ประกาศ ธปท. ล่าสุด ผลเทียบแต่ละข้อ และงานที่แบ่งให้พนักงาน พร้อมปุ่มอนุมัติ / ไม่อนุมัติ / ปิดงาน
- **งานอัตโนมัติทุกวัน 07:30 น.** – Vercel Cron เรียก `/api/cron` ดึงประกาศใหม่ วิเคราะห์ สร้างงาน แบ่งงาน และส่งอีเมลสรุป
- **อีเมลสรุปทุกเช้า** – งานใหม่ของแต่ละคนและงานที่เลยกำหนด ส่งผ่าน [Resend](https://resend.com)
- **ร่างประกาศที่เปิดรับฟังความเห็น** – เตือนล่วงหน้าพร้อมจำนวนวันที่เหลือก่อนปิดรับ
- **รายงาน** – กราฟงานค้างแยกตามฝ่าย ประกาศรายเดือน งานเลยกำหนด ส่งออก Excel (CSV) และพิมพ์ / บันทึก PDF
- **รายละเอียดงาน** – ประวัติ คอมเมนต์ และลิงก์หลักฐาน
- **ประกาศยาว** – แบ่งอ่านเป็น 2 ช่วง (สูงสุด 18,000 ตัวอักษร) แล้วรวมผล
- **วิเคราะห์ประกาศ** – วางข้อความ เลือกหัวข้อตัวอย่าง หรือเลือก PDF แล้วเทียบกับธนาคารที่เลือก
- **Human-in-the-loop** – งานที่ AI ไม่มั่นใจ (confidence < 0.8), ขัดกับ policy, มาจากร่างประกาศ
  หรือเป็นของธนาคารจริง ต้องให้คนอนุมัติก่อนเสมอ กติกานี้บังคับในโค้ด
- **TH / EN** – เปลี่ยนภาษาทั้งหน้าเว็บ และ AI ตอบผลวิเคราะห์ตามภาษาที่เลือก
- **คลังเอกสาร**, **ประวัติ** และ **Policy ธนาคาร**

## แหล่งข้อมูล

| ข้อมูล | ที่มา |
|---|---|
| ร่างรับฟังความเห็น | หน้า [การเปิดรับฟังความคิดเห็น](https://www.bot.or.th/th/laws-and-rules/public-hearing.html) ของ ธปท. |
| ประกาศ ธปท. | ระบบ [FIPCS](https://app.bot.or.th/FIPCS/Thai/PFIPCS_List.aspx?docgroup=1) ของ ธปท. ดึงรายการและอ่านข้อความจาก PDF จริง (`lib/bot.js`) |
| นโยบายธนาคารจริง | สรุปจากเอกสารที่ธนาคารเผยแพร่บนเว็บไซต์ของตัวเอง พร้อมลิงก์ที่มา (`lib/banks.js`) |
| Bank A | policy สมมติสำหรับ demo (`lib/policies.js`) |
| ผู้ใช้ / พนักงาน | รายชื่อสมมติ: หัวหน้า 1 คน + พนักงาน 10 คนใน 7 ฝ่าย (`lib/staff.js`) |

> นโยบายภายในจริงของธนาคารไม่เปิดเผยต่อสาธารณะ ระบบจึงเทียบกับ **เอกสารนโยบายที่ธนาคารเผยแพร่** (เช่น AML/CFT, ความปลอดภัยไซเบอร์)
> ผลจึงเป็นการชี้ประเด็นให้คนตรวจต่อ ไม่ใช่ข้อสรุปว่าธนาคารทำผิดกฎ งานของธนาคารจริงทุกงานจึงต้องให้คนอนุมัติก่อน

## การทำงาน

```
ทุกวัน 07:30 (Vercel Cron) หรือปุ่ม "รันตอนนี้"
  └─ lib/daily.js
       1. lib/bot.js     ดึงรายการประกาศ ธปท. จาก FIPCS → เอาฉบับใหม่ → อ่านข้อความจาก PDF
       2. lib/agent.js   ส่งประกาศ + นโยบายของแต่ละธนาคารให้ Groq (1 ครั้งต่อธนาคาร, ตอบเป็น JSON)
       3. โค้ดตรวจผล     สถานะถูกต้อง, policy มีอยู่จริง, ข้ามประกาศที่ไม่ได้ส่งถึงธนาคารพาณิชย์
       4. lib/staff.js   สร้างงานแล้วแบ่งให้คนในฝ่ายที่มีงานค้างน้อยที่สุด
       5. lib/db.js      บันทึกลง Neon Postgres (หรือไฟล์ .data/state.json ตอนรันในเครื่อง)
       6. lib/notify.js  ส่งอีเมลสรุปงานใหม่และงานที่เลยกำหนด
```

Groq free tier จำกัด 8,000 tokens ต่อนาที และ 200,000 tokens ต่อวัน (ประกาศ 1 ฉบับต่อ 1 ธนาคารใช้ราว 5,000–7,000 tokens)
งานประจำวันจึงทำทีละคู่ (ประกาศ × ธนาคาร) ภายใน 4 นาที ที่เหลืออยู่ในคิวและทำต่อในรอบถัดไป
และจะดึงประกาศใหม่ (ทีละ 1 ฉบับ) เฉพาะเมื่อคิวว่าง คิวจึงไม่ยาวขึ้นเรื่อย ๆ
มี lock ให้รันได้ทีละรอบ (cron กับปุ่ม "รันตอนนี้" ไม่ชนกัน) และโหลดข้อมูลล่าสุดก่อนบันทึกทุกครั้ง การอนุมัติระหว่างรันจึงไม่หาย

```
app/
  page.js               หน้าจอทั้งหมด
  i18n.js               คำแปล TH / EN
  store.js              ข้อมูลหน้าวิเคราะห์ฝั่งเบราว์เซอร์ (localStorage)
  api/analyze           วิเคราะห์ประกาศด้วย AI
  api/daily             GET สรุปของธนาคาร · POST รันงานประจำวันทันที
  api/cron              จุดที่ Vercel Cron เรียกทุกเช้า
  api/tasks             อนุมัติ / ไม่อนุมัติ / ปิดงาน / คอมเมนต์ / ลิงก์หลักฐาน
  api/auth              เข้าสู่ระบบ / ออกจากระบบ
  api/hearings          ร่างประกาศที่เปิดรับฟังความเห็น
  api/extract           ดึงข้อความจาก PDF ที่อัปโหลด
  api/status            บอกว่าเปิดใช้ AI อยู่หรือไม่
lib/
  agent.js   prompt และการตรวจผลจาก AI
  bot.js     ดึงประกาศ ธปท.
  banks.js   ธนาคารและนโยบาย
  daily.js   งานประจำวัน
  db.js      ที่เก็บข้อมูล
  staff.js   ผู้ใช้ พนักงาน และการแบ่งงาน
  auth.js    ล็อกอินด้วย cookie ที่เซ็นด้วย HMAC และตรวจสิทธิ์
  notify.js  อีเมลสรุปประจำวัน
  groq.js    เรียก Groq API
vercel.json  ตั้งเวลา cron (30 0 * * * = 07:30 เวลาไทย)
```

## รันในเครื่อง

ต้องมี Node.js 20 ขึ้นไป

```bash
npm install
cp .env.example .env.local
```

ใส่ใน `.env.local`:

```
GROQ_API_KEY=gsk_...                   # จาก https://console.groq.com/keys
GROQ_MODEL=openai/gpt-oss-120b
DATABASE_URL=                          # ไม่ใส่ก็ได้ ตอนรันในเครื่องจะเก็บที่ .data/state.json
CRON_SECRET=                           # ใช้บน Vercel
AUTH_SECRET=                           # สุ่มข้อความยาว ๆ ใช้เซ็น cookie
MANAGER_PASSWORD=                      # รหัสผ่านของหัวหน้า
STAFF_PASSWORD=                        # รหัสผ่านของพนักงาน
RESEND_API_KEY=                        # ไม่ใส่ = ไม่ส่งอีเมล
NOTIFY_EMAIL=                          # อีเมลผู้รับสรุป (คั่นด้วย ,)
APP_URL=http://localhost:3000          # ลิงก์ในอีเมล
```

```bash
npm run dev
```

เปิด http://localhost:3000 เข้าสู่ระบบเป็นหัวหน้า เลือกธนาคารที่มุมขวาบน แล้วกด **รันตอนนี้** ในหน้าสรุปประจำวัน

## Deploy บน Vercel

1. Import repo นี้ใน Vercel
2. สร้างฐานข้อมูล Neon Postgres (Vercel Marketplace หรือ neon.tech) แล้วใส่ `DATABASE_URL`
3. Settings → Environment Variables ใส่ `GROQ_API_KEY`, `GROQ_MODEL`, `DATABASE_URL`, `CRON_SECRET`,
   `AUTH_SECRET`, `MANAGER_PASSWORD`, `STAFF_PASSWORD` (ถ้าไม่ใส่ 3 ตัวหลัง จะเข้าสู่ระบบไม่ได้)
   และถ้าต้องการอีเมล: `RESEND_API_KEY`, `NOTIFY_EMAIL`, `APP_URL`
4. Deploy แล้ว cron ใน `vercel.json` จะเริ่มทำงานเอง (แพ็กเกจ Hobby รันวันละครั้ง เวลาอาจคลาดภายในชั่วโมงนั้น)
